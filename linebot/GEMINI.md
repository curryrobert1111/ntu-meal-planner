# 讓 LINE Bot 用 Gemini 自由對話

設定好之後，固定指令（菜單、80、飲料、全素…）照舊直接處理，**不花錢、不經過 AI**；
只有 bot 看不懂的句子，例如「公館有什麼便宜的拉麵」「今天下雨想在校內吃」，才交給 Gemini 回答。

Gemini 只負責「聽懂」和「說話」。店名、價格、營業時間都由 bot 從 `js/data.js` 查好再交給它，
系統指示也規定它不能自己編，所以不會出現資料裡沒有的店或價格。

---

## 1. 申請 Gemini API 金鑰（免費，約 3 分鐘）

1. 打開 [Google AI Studio](https://aistudio.google.com/)，用 Google 帳號登入。
   第一次會要你同意服務條款。
2. 左側（或右上）點「**Get API key**」→「**Create API key**」。
   要你選專案時，可以選「Create API key in new project」，或選現有的 Google Cloud 專案。
3. 複製產生的金鑰（`AIza` 開頭的一長串）。

> **金鑰等於密碼**：不要貼到 GitHub、群組或截圖。外洩的話，到同一頁把金鑰刪掉、重新建立一把。

### 免費方案還是付費？

| | 免費方案（預設） | 付費方案 |
|---|---|---|
| 費用 | 0 元 | 依用量計費；預設模型 gemini-3.5-flash-lite 一則約台幣 1 毛 |
| 限制 | 每分鐘、每天有次數上限，超過會回「太忙了」 | 上限高很多 |
| 資料 | 依 Google 條款，免費方案的內容**可能被用來改進 Google 的產品** | 不會被拿去訓練 |
| 怎麼開 | 什麼都不用做 | AI Studio →「Billing」綁定 Google Cloud 帳單帳戶，並設定**每月花費上限** |

先用免費方案測試即可。要正式給很多同學用，或擔心使用者的訊息被拿去用，再開付費方案。

---

## 2. 把金鑰設定到伺服器

在 bot 的部署平台新增環境變數（名稱要完全照抄）：

| 名稱 | 值 | 必填 |
|---|---|---|
| `GEMINI_API_KEY` | 第 1 步的金鑰 | 是 |
| `GEMINI_MODEL` | 不填就用 `gemini-3.5-flash-lite`。Google 下架舊模型時，錯誤訊息會告訴你新名稱，改這個變數就好，不用改程式 | 否 |
| `AI_DAILY_LIMIT` | 每位使用者每天最多幾則 AI 回覆，預設 `30` | 否 |
| `AI_GLOBAL_LIMIT` | 整個 bot 每天最多幾則 AI 回覆，預設 `1500` | 否 |

- **Render**：服務頁面左側「Environment」→「Add Environment Variable」→ 儲存，會自動重新部署。
- **Cloud Run**：服務頁面 →「編輯並部署新的修訂版本」→「變數與密鑰」→ 新增 → 部署。

本機測試的話，寫在 `linebot/.env`（這個檔案不會被推上 GitHub）。

---

## 3. 推上新程式

這次新增／修改的檔案：

- `linebot/gemini.js`：串接 Gemini、提供查詢工具、對話紀錄、每日上限
- `linebot/index.js`：固定指令看不懂時改交給 Gemini
- `linebot/.env.example`：多了 Gemini 的變數說明

```
git add linebot/
git commit -m "LINE Bot 串接 Gemini 自由對話"
git push
```

Render／Cloud Run 會自動重新部署。部署完成後看記錄（Logs），出現
`LINE bot listening on :xxxx（AI 對話：開啟）` 就代表有讀到金鑰；
如果寫「未設定 GEMINI_API_KEY，關閉」，回第 2 步檢查變數名稱。

## 4. 測試

用手機傳這些句子給官方帳號：

| 傳什麼 | 預期 |
|---|---|
| `公館有什麼便宜的拉麵` | 列出公館的拉麵與價格 |
| `今天下雨不想走遠，校內 80 塊的午餐` | 列出校內約 80 元的午餐 |
| `50嵐幾點關門` | 回答營業時間 |
| `我吃全素，幫我排這週菜單，預算 1500` | 改成全素、預算 1500，並附上一週菜單與完整表格連結 |
| `剛剛那家還有別的嗎` | 能接著上一句回答（會記住 30 分鐘內最近 6 輪對話） |
| `明天天氣如何` | 友善地拉回吃飯的話題 |
| `菜單`、`80`、`飲料` | 和以前一樣，走固定指令 |

## 5. 它可以做什麼（工具）

| 工具 | 用途 |
|---|---|
| `search_food` | 依價格、類別（正餐／早餐／午餐／晚餐／飲料／咖啡／點心）、區域、關鍵字找今天有營業的餐點，每家店最多 2 道、最多 8 筆 |
| `store_info` | 查某家店的地點、營業時間、價格範圍、部分菜單 |
| `make_week_plan` | 排一週菜單；完整菜單和「完整表格」連結由系統直接附在回覆後面，不讓 AI 改寫 |
| `update_preferences` | 修改預算、素食、穆斯林、忌口、區域 |
| `get_preferences` | 查看目前條件 |

想調整 AI 的語氣或規則，改 `gemini.js` 裡的 `systemPrompt()`。

## 6. 常見問題

| 狀況 | 原因與解法 |
|---|---|
| 自由對話都回「看不懂這個指令」 | 沒讀到金鑰，或呼叫 Gemini 失敗。看記錄裡 `[gemini]` 開頭的錯誤 |
| 記錄出現 `Gemini 400 … API key not valid` | 金鑰貼錯（多了空白？），重新複製 |
| 記錄出現 `Gemini 403` | 金鑰被停用，或所在專案沒有啟用 Gemini API；到 AI Studio 重建金鑰 |
| 記錄出現 `Gemini 404 … model … no longer available` | 模型已下架或名稱打錯。錯誤訊息會寫建議的新模型（例如 `gemini-3.5-flash-lite`），把它填進 `GEMINI_MODEL` |
| 回「AI 小幫手現在太忙了」 | 超過免費方案的速度限制（429），等一分鐘再試；常發生就改付費方案 |
| 回「今天的 AI 對話次數已經用完了」 | 達到 `AI_DAILY_LIMIT`，隔天（台灣時間）重置 |
| AI 回答的店家或價格怪怪的 | AI 只會用資料裡的內容；請檢查 `js/data.js` 那筆資料是否正確 |
| 第一則訊息沒回應 | Render 免費方案休眠中，見前面的說明（cron-job.org 或改用 Cloud Run） |

## 7. 費用控制

- 每人每天 30 則、全站每天 1,500 則的上限已經寫在程式裡，可用環境變數調整。
- 開付費方案的話，一定要在 Google Cloud「帳單 → 預算與快訊」設預算提醒，
  並在 AI Studio 的 Billing 頁面設定花費上限。
- 對話紀錄、每日次數都存在記憶體；伺服器重新啟動或休眠後會清空，計數也會重來。
